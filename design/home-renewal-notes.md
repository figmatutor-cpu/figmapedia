# 홈 개선 기록

## 구조

- `src/app/page.tsx`: 홈과 기존 검색 결과의 전환.
- `src/components/home/WorkflowHome.tsx`: 워크플로우 교육·컨설팅 소개, 자료실, 문의.
- `src/components/home/HomeNavigation.tsx`: 홈 전용 반응형 내비게이션.
- `src/components/home/LectureHistory.tsx`: 반복 교육·자문 요약과 전체 이력 검색.
- `src/data/lectures.json`: CSV에서 생성한 공개 이력.
- `scripts/sync-lectures.py`: 원본 갱신 후 공개 데이터 재생성.
- `src/components/layout/Navbar.tsx`: 홈과 자료실의 메뉴 선택.
- `src/app/layout.tsx`: 검색·공유용 메타데이터.

## 발견한 문제와 변경

기존 홈은 전체 화면의 배경 효과와 검색창으로 시작해, 교육·컨설팅 담당자가 누구에게 무엇을 의뢰할 수 있는지 알기 어려웠다. 도구 목록보다 업무의 병목, 재사용, 협업이라는 과제를 먼저 제시하고 진단·교육·적용의 진행 방식을 연결했다.

실제 이력이 홈에 없었다. CSV의 강의 진행 기록 전체를 기관·분야·시기·횟수 형태로 공개하고, 반복 교육과 확인 가능한 자문을 강조했다. 문의 상태는 실적으로 사용하지 않았다. 기관별 강의 주제와 성과는 제공 자료에 없어 추가하지 않았다.

고정 검색창과 커뮤니티 모집 버튼이 주요 행동을 차지했다. 검색은 자료실에, 커뮤니티 가입은 그 아래에 배치하고 홈의 주요 행동은 교육·컨설팅 문의로 통일했다. 검색 결과 화면의 검색창은 유지했다.

모바일 메뉴는 닫힌 상태에서 링크가 포커스되지 않도록 처리했다. 홈 메뉴에는 Escape 닫기, 상태 전달, 본문 건너뛰기 동선을 추가했다.

## 검증 범위

CSV 106개 공개 행의 원문 일치, 18개 문의·미팅 제외, 자문 1건 반영을 독립 비교했다. 변경 파일 ESLint 및 TypeScript 검사를 통과했다. 개발 서버의 홈 HTTP 200 응답에서 제목 구조, 모든 내부 앵커, 106개 기관 렌더링과 문의 이력 제외를 확인했다. 프로덕션 빌드는 기존 Supabase 환경변수가 있어야 페이지 데이터 수집까지 완료할 수 있다. 이 환경에는 연결된 브라우저가 없어 시각·클릭 검증은 별도 확인이 필요하다.

기존 자료실 검색은 Notion API 토큰이 없어 로컬에서 401 응답을 반환한다. Supabase 및 Notion 환경 설정 후 데이터 연동 검증이 필요하다.

## Figmatutor 독립 발행

`sites/figmatutor`는 소개 페이지와 공개 이력만 포함하는 정적 Next.js 사이트다. `python3 scripts/prepare-figmatutor.py`로 공유 화면을 복사한 뒤 별도로 빌드·배포한다. 실무자료실과 커뮤니티 메뉴는 각각 huddling.ai와 huddling.club으로 이동한다. 자료실 목록의 세부 링크도 huddling.ai로 연결한다. 소개 사이트에는 CMS 검색 요청과 관련 비공개 환경변수 의존성이 없다.
